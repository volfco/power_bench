# Assumptions

- Data source is `power_meter.duckdb` in the repo root; it currently has 0 runs / 0 readings, so the report renders empty states until benchmark runs are recorded.
- "0/25/75/100" config scale = EPP-style spectrum: 0 max performance, 25 performance, 75 powersave, 100 max powersave; `optimization` names map onto it by substring (see `map_scale` in scripts/export_report_data.py).
- `power_meter.duckdb` is stored in git LFS (`.gitattributes` tracks it); the DB must actually be committed through a machine with git-lfs installed before the deploy workflow has data to read.
- Site is served from `site/` on GitHub Pages as static files; `data.json` is regenerated by `.github/workflows/deploy-report.yml` on every push touching the DB or report sources.
- Prior dashboard.py / report generators / GitHub workflows are abandoned; not referenced by the new report.
